# سنتــــر الأزهر

متجر إلكتروني عربي مبني بـ React وNestJS وSQLite.

## التشغيل

```powershell
npm install
npm run dev
```

- واجهة المتجر: http://localhost:5173
- API: http://127.0.0.1:3001
- قاعدة البيانات: `.data/al-azhar-store.sqlite`

## تطبيقات الكمبيوتر والهاتف

تستخدم التطبيقات نفس واجهة الموقع. يُبنى تطبيق الكمبيوتر بـTauri (Windows ‏32-bit و64-bit وARM64، وmacOS ‏Intel وApple Silicon، وLinux ‏DEB/RPM)، وتُبنى تطبيقات Android وiOS بـCapacitor.

تحتاج كل التطبيقات إلى نسخة API عامة تعمل عبر HTTPS؛ ملف SQLite والخادم لا يُضمّنان داخل التطبيق. انشر API على خادمك واضبط:

- `HOST=0.0.0.0`
- `NODE_ENV=production`
- `CORS_ORIGINS=https://عنوان-الموقع-العام`
- `VITE_API_BASE_URL=https://عنوان-API-العام` عند بناء تطبيقات الواجهة (دون `/api`)

يُسمح تلقائيًا بمصادر Tauri وCapacitor المحلية. اضبط `CORS_ORIGINS` أيضًا لأي موقع ويب عام يستخدم الـAPI. لا تضع مفاتيح chatbot أو Paymob في إعدادات تطبيق الواجهة؛ تبقى على الخادم فقط.

للبناء محليًا، جهّز Rust وبيئة Tauri الخاصة بنظام التشغيل، ثم:

```powershell
npm ci
$env:VITE_API_BASE_URL = "https://api.example.com"
npm run build:desktop -- --bundles nsis
```

يمكن تجهيز Android بـAndroid Studio/SDK وJava 21 عبر `npx cap add android` ثم `npm run mobile:sync`، وتجهيز iOS بـXcode على macOS عبر `npx cap add ios` ثم `npm run mobile:sync`. ينفذ سير عمل GitHub عمليات بناء كل المنصات عند تشغيله يدويًا أو عند دفع وسم إصدار `v*`.

أضف متغير المستودع `VITE_API_BASE_URL` في GitHub Actions قبل البناء. نواتج iOS غير موقعة، وتوزيعها أو رفعها إلى App Store يتطلب شهادة وحساب Apple Developer؛ وتوقيع Android للنشر يتطلب مفتاح رفع. حزم Windows غير موقعة افتراضيًا.

## إعداد مدير المتجر

التسجيل العام ينشئ حساب عميل فقط ولا يمنح صلاحية أدمن. لإعداد مدير أو ترقية حساب موجود، شغّل الأمر من الجهاز المضيف ثم أدخل بيانات المدير بنفسك:

```powershell
npm run admin:setup
```

## نظام الحسابات

- التسجيل وإنشاء الجلسة حقيقيان.
- لا يوجد حساب أدمن أو كلمة مرور افتراضية.
- يستطيع الأدمن تعطيل حساب عميل فيُرفض تسجيل دخوله وتُبطل جلساته، أو حذفه نهائيًا. تُحفظ الطلبات التاريخية بعد فصلها عن الحساب المحذوف.
- حسابات الإدارة محمية من صفحة إدارة العملاء.
- كلمات المرور تُجزّأ باستخدام scrypt.
- الجلسة تحفظ بصمة الرمز فقط في قاعدة البيانات داخل Cookie HttpOnly.

## المساعد الذكي

المساعد يستدعي نموذجًا حقيقيًا متوافقًا مع OpenAI Chat Completions من الخادم، ويستخدم قائمة المنتجات الحالية وأسعارها ومخزونها كسياق. لا توجد إجابات تجريبية احتياطية. انسخ `.env.example` إلى `.env`، واستبدل قيمة `CHATBOT_API_KEY` بمفتاح Google AI Studio. اترك `CHATBOT_API_URL` كرابط URL ولا تضع فيه أمر `curl`. أعد تشغيل خادم API بعد تعديل `.env`. لا تضع المفتاح في الواجهة أو تشاركه بالمحادثات؛ من دون مفتاح، يعرض الموقع رسالة واضحة بأن المساعد غير مفعّل.

## الشراء والإدارة

- تصفح المنتجات والتصنيفات والبحث.
- سلة محفوظة في المتصفح.
- طلبات بالدفع عند الاستلام، أو الدفع الإلكتروني عبر Paymob بعد ضبط مفاتيح التاجر.
- لوحة إدارة للطلبات وتغيير حالة الطلب.

## الدفع الإلكتروني عبر Paymob

1. أنشئ حساب تاجر لدى Paymob، وأكمل تفعيل بوابة الدفع والحساب البنكي/المحفظة.
2. انسخ مفاتيح API وHMAC ومعرّف التكامل ورقم iframe من حساب Paymob إلى `.env` على الخادم فقط، باستخدام الأسماء الموجودة في `.env.example`.
3. استبدل عنواني `PAYMOB_NOTIFICATION_URL` و`PAYMOB_RETURN_URL` بعناوين HTTPS عامة للموقع؛ نقطة الإشعار هي `/api/payments/paymob/webhook` وصفحة العودة هي `/payment-result`.
4. ابدأ بمفاتيح الاختبار، وتأكد من نجاح إشعار HMAC وتحديث الطلب، ثم بدّل إلى بيانات الإنتاج بعد اختبار دورة الدفع والاسترداد مع Paymob.

لا يظهر خيار Paymob للعميل إلا إذا اكتملت الإعدادات. لا تحفظ بيانات البطاقات في المتجر؛ تتم عملية الدفع على صفحة Paymob. يظل الدفع عند الاستلام متاحًا دون إعداد حساب Paymob. الطلب الإلكتروني غير المدفوع يُلغى بعد ساعة وتُعاد كمياته للمخزون؛ أي إشعار دفع متأخر أو غير مطابق يُعلَّم للمراجعة بدل تأكيده تلقائيًا.
